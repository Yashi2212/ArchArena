# Competitor evidence and positioning

Public vendor descriptions inspected on November 18, 2026. This is a small desk-research sample, not hands-on testing or a market-wide uniqueness audit. Vendor claims do not establish quality. Do not infer an absent feature merely because a public page omits it.

| Product and primary source | Publicly described offering | What ArchArena should learn / validate |

## Differentiator to prove

Proposed first-release positioning: **A Java-focused, reproducible system design lab where lessons and Practice scorecards use the same bounded server-side model, and feedback points to exact run metrics and stated assumptions.**

The claim is about ArchArena's intended behavior, not competitor absence. “Feedback grounded in simulation” is only substantiated after provenance checks, engine validation and critique-citation tests exist. The future Design Studio contribution is versioned consistency checking from requirements to LLD, combining explicit rules with separately labeled AI suggestions. It is not part of the first-release demo and must not appear as a completed feature on a resume.

## Validation before public positioning

1. Recheck current competitor offerings with the same URL-shortener workflow, documenting date, access level and evidence. Do not use pricing or access assumptions from this page.
2. Compare reproducibility (seed/version), declared modeling assumptions, feedback citation checks and artifact traceability. Mark unknown features “unknown,” not “no.”
3. Ask three Java developers whether the repeatable experiment and explanation loop is useful beyond a static diagram or AI conversation. Record actual answers and completion observations.
4. Publish only claims supported by the implemented demo and tests. Avoid “unique,” “industry first,” “production accurate,” and guaranteed interview outcomes.
